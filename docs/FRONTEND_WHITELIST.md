# Интеграция вайтлиста на фронте

## Когда показывать UI вайтлиста

- В публичном ответе по серверу приходит поле **`is_whitelist`** (boolean).
- Показывать кнопку/блок «Подать заявку в вайтлист» только если **`is_whitelist === true`**.
- Для серверов без вайтлиста этот блок не отображать.

## Страница сервера (публичная)

### 1. Получение статуса заявки

Перед отрисовкой блока вайтлиста, фронтенд должен запросить статус заявки текущего пользователя:
- **GET** `/api/v1/game-servers/{server_id}/whitelist/my-status` (требует авторизацию)
- Ответ: `{ "status": "approved" | "pending" | "rejected" | null, ... }`

### 2. Логика отображения

1. **Если `status === "approved"`**:
   - Пользователь уже в вайтлисте.
   - **Скрываем** кнопку «Подать заявку» и форму.
   - Можно показать плашку «Вы в вайтлисте ✅».

2. **Если `status === "pending"`**:
   - Заявка на рассмотрении.
   - **Скрываем** кнопку подачи.
   - Показываем статус: «Ваша заявка на рассмотрении ⏳».

3. **Если `status === "rejected"`**:
   - Заявка отклонена.
   - Показываем статус: «Заявка отклонена ❌».
   - Можно показать кнопку «Подать повторно» (открывает форму/отправляет запрос заново).

4. **Если `status === null` (нет заявки)**:
   - Показываем стандартный UI подачи заявки (кнопка → авто-запрос или форма, см. ниже).

### 3. Подача заявки (если status === null)

#### Если пользователь авторизован

1. **Проверить привязку Minecraft-аккаунта:**
   - Фронтенд должен проверить наличие привязанного аккаунта Minecraft (например, через эндпоинт `/api/v1/auth/check-link-status/{user_id}` или аналогичный, где возвращаются `ExternalLink`).
   - Искать линк с `platform: "MC"` (или как она именуется в системе).

2. **Сценарий А: Аккаунт Minecraft привязан**
   - Показать кнопку «Подать заявку в вайтлист» (или «Вступить в вайтлист»).
   - По нажатию: **автоматически** отправить запрос на `/apply`, подставив ник из привязанного аккаунта (`platform_username`).
   - Форму ввода ника **не показывать**.
   - После успешной отправки — показать сообщение об успехе.

3. **Сценарий Б: Аккаунт Minecraft НЕ привязан**
   - Показать кнопку «Подать заявку в вайтлист».
   - По нажатию: открыть **форму/модалку** с полем для ввода ника (обязательное).
   - Пользователь вводит ник вручную и отправляет форму.

### Если пользователь не авторизован

- Не давать подавать заявку. Можно показать ту же кнопку с подсказкой «Войдите, чтобы подать заявку» или скрыть блок.

## API заявки (пользователь)

- **Метод и путь:** `POST /api/v1/game-servers/{server_id}/whitelist/apply`
- **Авторизация:** обязательна (JWT в cookie или заголовок `Authorization: Bearer ...`).
- **Тело запроса:** JSON с полем `nickname` (строка, обязательное).
- **Ответ при успехе:** 201, в теле `message`, `entry_id`, `status` (например `"pending"`).
- **Ошибки:** 401 — не авторизован; 400 — сервер без вайтлиста, некорректный ник или такой ник уже в вайтлисте/уже есть заявка.

## Админка

### Список заявок (Pending)

- **Эндпоинт:** `GET /api/v1/admin/whitelist/pending`
- **Параметр:** `server_id` (опционально).
- **Ответ:** массив заявок со статусом `pending`.

### Список одобренных (Approved)

- **Эндпоинт:** `GET /api/v1/admin/whitelist/approved`
- **Параметр:** `server_id` (опционально).
- **Ответ:** массив записей со статусом `approved`.
- Здесь можно показывать список текущих игроков в вайтлисте и кнопку удаления.

### Принять заявку

- **Метод и путь:** `POST /api/v1/admin/whitelist/entries/{entry_id}/approve`
- **Авторизация:** админ.

### Отклонить заявку (или удалить из вайтлиста)

- **Метод и путь:** `POST /api/v1/admin/whitelist/entries/{entry_id}/reject`
- **Авторизация:** админ.
- Меняет статус на `rejected`. Если пользователь был `approved`, он потеряет доступ.

### Полное удаление записи

- **Метод и путь:** `DELETE /api/v1/admin/whitelist/entries/{entry_id}`
- **Авторизация:** админ.
- Полностью удаляет запись из БД (пользователь сможет подать новую заявку с нуля).

### Добавить в вайтлист вручную (без заявки)

- **Метод и путь:** `POST /api/v1/admin/whitelist/add`
- **Авторизация:** админ.
- **Тело:** JSON: `server_id` (UUID), `nickname` (строка). Опционально `user_id` (UUID) — привязать запись к пользователю.
- Ник добавляется сразу в статусе «одобрен»; заявка от пользователя не нужна.

## Настройка сервера (админка)

При создании и редактировании игрового сервера есть поле **«Вайтлист»** (чекбокс). Если оно включено, у сервера в публичном API будет `is_whitelist: true` и на фронте нужно показывать блок подачи заявки (для авторизованных) и в админке — работу с заявками и ручное добавление в вайтлист.

## Кратко по потокам

1. **Пользователь:** заходит на страницу сервера → видит кнопку вайтлиста только при `is_whitelist` и будучи авторизованным → вводит ник → отправляет заявку (POST apply).
2. **Админ:** открывает раздел заявок вайтлиста → видит список pending → принимает или отклоняет; при необходимости добавляет ник вручную через форму «Добавить в вайтлист» (сервер + ник).
